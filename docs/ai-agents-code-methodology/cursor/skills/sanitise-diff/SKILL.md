# sanitise-diff

## When to use

- Before claiming ready to hand off / commit.
- After staging a change (`git add`).
- User asks to sanitise or scrub the diff.

## Procedure

1. Inspect **staged** diff; consider **added** lines only (`+`), not removals.

```bash
git diff --cached
# or: git diff --cached | grep '^+' | grep -v '^+++'
```

2. Flag hits for (adapt patterns to repo `CONVENTIONS.md` / policy):

   - Secrets: API keys, tokens, passwords, private URLs with embedded creds.
   - Forbidden names / customer identifiers (from local policy).
   - Internal ticket ids embedded in **code** (docs under `data/changes/` may allow them).
   - Agent self-attribution (“Generated by …”, “Co-Authored-By: Cursor/Claude”, etc.) in shipped artifacts.

3. Exclude intentional local-only / gitignored paths from panic; still report them if staged by mistake.

4. Fix or unstage problems; re-run until clean.

## Output format

```text
Sanitise report
- Staged files: …
- Added-line scan: CLEAN | HITS
- Hits: <file:reason> …
- Actions taken: …
- Ready for human handoff: yes/no
```

Never skip because “this one looks clean.”
